---
name: task-kickoff
description: Interview the user to clarify a complex task, then write a spec.md. Use when the user wants to start a new complex task, feature, or design.
---

Run a /grilling session on the task.
When the interview reaches a shared understanding, write spec.md in the project root (or a location the user specifies) covering:

Goal — what we're building and why
Constraints — what's fixed (tech, time, scope)
Open decisions — anything unresolved that future sessions must address
Out of scope — what we explicitly are not doing

spec.md is the single source of truth for the task. Future sessions should read it before starting work.
